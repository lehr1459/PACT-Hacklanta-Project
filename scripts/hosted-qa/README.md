# Independent hosted API acceptance

Run from the repository root with the pinned Node runtime and installed hosted-service dependencies:

```text
node --test scripts/hosted-qa/phase1.test.mjs
node --test --test-concurrency=1 scripts/hosted-qa/phase1.test.mjs scripts/hosted-qa/phase2.test.mjs
node --test --test-concurrency=1 scripts/hosted-qa/gateway-integration.test.mjs scripts/hosted-qa/phase1.test.mjs scripts/hosted-qa/phase2.test.mjs scripts/hosted-qa/phase3.test.mjs
node --test --test-concurrency=1 scripts/hosted-qa/gateway.test.mjs scripts/hosted-qa/gateway-integration.test.mjs scripts/hosted-qa/phase1.test.mjs scripts/hosted-qa/phase2.test.mjs scripts/hosted-qa/phase3.test.mjs scripts/hosted-qa/phase4.test.mjs
```

The harness uses native PostgreSQL, actual loopback HTTP requests and disposable Ed25519 wallets. It does not import production signing, base58 or canonicalization helpers. It creates a separate `pact_hosted_qa` database and new random principals each run; it does not truncate an existing schema or stop the database service. Repeated runs retain test records in the disposable cluster.

By default it connects to the ignored local QA PostgreSQL fixture on port 55439 using explicitly synthetic test credentials. CI may supply `PACT_QA_DATABASE_URL` with its local PostgreSQL connection string. The safety guard requires exact host `127.0.0.1` and database `/pact_hosted_qa`; the supplied test database user must be allowed to create that database if absent. Never supply a production database.

Phase 1 covers two-admin tenant isolation, CSRF/origin and browser bindings, exact action/payload/session proofs, replay and concurrent consumption, concurrent partial updates, callback canonicalization/DNS renewal/revocation, key metadata and verifier storage, rotation overlap/revocation, process/connection restart, database unavailability, application quota races and rotation quota limits. Credential tests exercise the actual backend-only `/v1/credentials/validate` HTTP endpoint; supplemental scope checks call the exported verifier. Subsequent phases must also verify actual key-authenticated licensing HTTP access routes.

These deterministic tests establish local behavior. They do not establish GitHub CI success, real-wallet acceptance, public hosting or a production security audit.

Phase 2 adds manually encoded Solana account fixtures served by an actual loopback HTTP RPC. The service uses the existing hardened SDK reader, preserving genesis/program/owner/PDA/Clock validation. Tests exercise signed seller ownership, invalid chain evidence, tenant/input restrictions, immutable keys, version history, epoch progression, concurrent version conflicts and emergency disable. The fixture permits only read RPC methods; it cannot submit a transaction. Hosted grants do not exist in this phase, so their epoch invalidation is tested later.

Phase 3 exercises custom backend-mediated wallet authentication with disposable signatures. Two independent service instances and database pools compete for one code; restarts, outage, exact binding, PKCE/state/issuer, wallet switch, revocation, policy epochs and strict TTLs are checked. The separate gateway integration uses actual HTTP and native PostgreSQL, without building Next. Grant checks use the real SQL verifier; subsequent access tests must verify fresh licensing HTTP decisions. These tests do not substitute for `/connect` browser UX or real Phantom acceptance.

Production `/connect` browser tests live in `web/tests/hosted/`. Run only from an isolated clean checkout with pinned dependencies/runtime, no active environment files, and the native PostgreSQL fixture. Set `PACT_HOSTED_QA_CLEAN=1`, run `node scripts/hosted-qa/build-web.mjs`, then `node web/node_modules/@playwright/test/cli.js test --config web/tests/hosted/playwright.config.ts`. The harness starts its own prebuilt Next listener on 3112, independent consumer on 3113 and ephemeral API listener; it does not build the root web tree or kill unrelated listeners. Production startup settings match the saved build binding. Desktop/320px tests use disposable Node-side signers; no key/grant enters browser code. The consumer fixture is test-only, uses a process-local HttpOnly session/state store and never claims production durability or real-wallet acceptance.

Phase 4 adds actual license account bytes and real HTTP authorization: missing/active/exact-expiry/deactivation, app-scoped key/grant swaps on a deliberately shared offer, chain corruption/history/outage/timeout, awaited-read revocation/pause/rebind races, original freshness after SQL overhead, lease deadlines, per-app fairness, HTTP/body-abort and SQL reservation, redacted telemetry, readiness and quotas. The readiness test briefly corrupts then restores one checksum in the QA-owned database; serialize this suite and do not run another worker against that database during it. All chain methods remain read-only.

The Phase 5 console suite runs in the same isolated prebuilt checkout using `node web/node_modules/@playwright/test/cli.js test --config web/tests/hosted/console.config.ts`. It deliberately exercises the admin-only one-time secret reveal. Its configuration disables tracing, videos, automatic screenshots and Playwright failure page snapshots; do not turn those artifacts on for these tests. Secret-bearing fixture calls use Node fetch, not recorded Playwright API requests. Only hashes of disposable signatures are retained. A manually captured screenshot is permitted only after the harness checks the page contains no full key or proof. After the run, execute `node scripts/hosted-qa/audit-console-artifacts.mjs web/test-results/hosted-console` from that checkout and audit the separate runner log too. Local consumer QA controls are confined to this guarded test process; they are not product routes.

Phase 6 independent additions are `phase6-contract.test.mjs` (static frozen OpenAPI route/security semantics and actual native malformed-proof consumption), `phase6-client.test.mjs` (the private client through real HTTP), and `phase6-consumer.test.mjs` (actual Express and production Next BFF wrappers using the private client, native PostgreSQL and the real hardened SDK). Run them serially with the earlier suites. The consumer test exercises missing/active/exact-expiry/outage decisions, server-only grant exchange, cookie rotation, CSRF, replay, a logout during an awaited chain read and actual persisted grant revocation. The Next case additionally restarts a previously licensed local session and requires fresh authentication.

For complete Next coverage, first build `examples/pact-hosted-next` in the isolated clean checkout. Set `PACT_QA_NEXT_EXAMPLE_BUILD` to that example's absolute directory before running `node --test --test-concurrency=1 scripts/hosted-qa/phase6-consumer.test.mjs`. This setting contains only a local directory. The harness generates its own ephemeral server key and passes it only in the owned child process environment, never command arguments, files or output. It chooses an ephemeral loopback port, checks for active environment files by existence only and stops only its own child. Without this setting the Next case is explicitly skipped; that result is not complete example acceptance.

## Complete hosted acceptance gate

Use a fresh committed checkout, pinned Node24.22.1/npm11.19.1, no active environment files and the dedicated loopback PostgreSQL fixture. Set `PACT_HOSTED_QA_CLEAN=1`; optionally set `PACT_QA_DATABASE_URL` only to that fixture. Run:

```text
node scripts/hosted-qa/run.mjs install
node web/node_modules/@playwright/test/cli.js install chromium
node scripts/hosted-qa/run.mjs all
node scripts/hosted-qa/artifact.mjs
node scripts/hosted-qa/export-receipts.mjs
```

Linux CI installs Chromium with `--with-deps`. `all` requires the complete explicit native suite (at least85cases), actual production Next consumer, API/client/example tests, contract drift, seven dependency graphs, private packed-client checks and16console+12connect browser checks. Node tests cannot be empty, failed, cancelled, skipped or todo. A run UUID and source revision bind the actual production web build and browser receipts. The initial tree must be clean; final source changes are rejected apart from exact generated Next type-reference contents. `portable` runs the cross-platform contract/client/example/reporting subset, not native database/browser acceptance.

Phase7 native cases cover real clock storage and process faults, absolute body/handler/header ceilings, bounded retention/erasure and isolated snapshot quarantine/rekey. They never truncate the shared QA database. The checksum drift probe still requires exclusive serialized database use. The finite load check uses24actual HTTP decisions across two apps at four concurrent reads, actual durable host-clock authority and synthetic raw RPC; it records numeric percentiles and outage recovery, not provider capacity or an SLA.

The production artifact driver makes a fresh allowlisted private production installation, excludes PGlite and development-only esbuild, and tests real HTTP readiness, administrator/key operations, graceful restart and revoke in its own uniquely named disposable database. The unchanged SDK retains TypeScript through Solana codecs' optional production peer dependency; it is not evidence of a failed `--omit=dev` install. No environment file or proprietary customer source is copied. On Linux with Docker available, add `--docker` to require a pinned two-stage image build and actual nonroot/read-only container smoke over host-loopback networking; no image is pushed. Its local-profile native-PostgreSQL smoke does not accept hosted TLS/provider configuration. Docker execution remains separate evidence when the local host lacks a daemon.

Raw child logs, clocks, backups and fixture material remain ignored/private. Both hosted browser configs disable traces/video/automatic screenshots and raw failure diagnostics. The auditor rejects raw cookies/proofs, recordings, page snapshots and unapproved rasters; it cannot certify image pixels. Export reconstructs only three fixed numeric/status summaries, rejects stale build/run/source bindings and refuses existing/linked output leaves. Use a fresh owned `hosted-export` directory for each export. CI uploads only those three files after scanning, never the raw test tree. Historical private image quarantine is never exported.

The existing original matrix remains `node scripts/validation/run.mjs all-node --clean` and Windows `all-chain`, followed by clean-source provenance rebuild. New remote jobs require owner-authorized push/run; local replay and the foundation's earlier green run are separate facts.

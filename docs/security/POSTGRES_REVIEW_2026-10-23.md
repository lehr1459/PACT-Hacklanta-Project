# PostgreSQL staging security review — October23, 2026

The inherited PostgreSQL18.4 CI/test pin is superseded for staging. The official [18.6 security release](https://www.postgresql.org/about/news/postgresql-186-1711-1615-1519-1424-and-19-beta-3-released-3365/) fixes28 vulnerabilities and additional bugs relative to18.4;18.5 was not shipped. Passing18.4 tests does not justify recommending that older server for new hosting. See the [security table](https://www.postgresql.org/support/security/18/) and [18.6 release notes](https://www.postgresql.org/docs/18/release-18-6.html).

The focused correction updates only the CI database image, staging Compose/preflight pin and operating instructions to the official `postgres:18.6-bookworm@sha256:bbf83594798e144bff365a9c191c5d779f181fb3135902064ab8ff11918020fc`. The Docker Hub official registry returned this index for18.6-bookworm and Linux amd64 child `sha256:6b38fe68f2c02cafffbbce7496f76d110d8a947c039bd22c067e9a43c2250240`. This fixes identity, not future advisory clearance. Recheck before hosting and on new advisories.

No existing PostgreSQL server/data directory was upgraded or replaced. Local validation creates an independent18.6 cluster on a different loopback port and retains earlier18.4 evidence. Native server/tools are extracted from the EDB archive already verified against its publisher SHA256 and [maintainer confirmation](https://github.com/EnterpriseDB/edb-installers/issues/746). Test credentials/certificates/backups are disposable private fixtures, never release payloads. No provider, production database, Supabase setting or public deployment is changed.

This remains PostgreSQL major18 with unchanged application schema/migration checksums. The release notes require special attention for certain pre-existing GIN indexes and `btree_gist`/`ltree` extensions. PACT's six migrations create none of those extensions/GIN indexes; the proposed staging database is new. Do not interpret this as approval to upgrade an unrelated existing database without inspecting its own schema/indexes/extensions and backup recovery.

Acceptance requires the native auth/tenant/clock/maintenance tests, actual portable dump/restore/quarantine, verified-TLS least-privilege checks and final exact-commit Linux CI against18.6. Node/npm, SDK/API source, legal protocol, Solana and Base are untouched. Full Linux Compose with Caddy, public-domain TLS/renewal, time/storage behavior and human Phantom acceptance remain owner-controlled gates even after those checks pass.

Local18.6 results:73 native security/recovery cases passed, zero skips; five TLS/durability/role/migration checks passed. Actual dump/restore used18.6 clients/server. The prior18.4 cluster stayed stopped and unchanged. Exact final-commit CI, artifact identity and full host acceptance are recorded separately; these local results are not hosting approval.

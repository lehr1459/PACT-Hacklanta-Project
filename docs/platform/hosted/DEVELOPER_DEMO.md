# Independent developer integration demonstration

`node scripts/hosted-qa/developer-demo.mjs` runs the complete deterministic hosted integration against actual HTTP, native PostgreSQL and the existing hardened Solana reader. Use the reviewed Node/npm versions from `scripts/validation/runtime.json`, install the existing API/SDK/example dependencies, and configure only the guarded local `PACT_QA_DATABASE_URL` described in [the acceptance harness](../../../scripts/hosted-qa/README.md). The database must be the disposable loopback `pact_hosted_qa`; never supply a staging or production database.

Use a clean committed checkout. The driver verifies and materializes the existing deterministic source kit from Git blobs before packing the actual private client, shared consumer engine and Express example. Ignored workstation files cannot enter these archives. It installs the packages into a fresh OS temporary directory outside PACT and starts that independently installed backend. Temporary npm overrides select the packed private dependencies in place of the repository-relative example paths. PACT's source is not modified, Vercel is not required, and nothing is published. The consumer contains the existing real protected GET `/api/protected` and POST `/api/action`, with no custom authorization substitute.

Three distinct disposable Ed25519 identities represent developer D, seller S and buyer B. Actual public HTTP operations authenticate admins, register applications, reject D binding S's offer, bind S's resource, register the exact consumer callback, mint a scoped credential and activate S's app. The separate backend initiates buyer login, owns state and PKCE, exchanges the one-use code and retains the grant in its private session. Signed-in buyers without a license cannot read or perform the protected operation. A manually encoded **synthetic RPC entitlement** then permits those operations. Logout/grant revocation, callback replay, key revocation and unrelated-tenant reads are exercised.

The fixture is not a blockchain purchase: it sends no transaction, uses no real wallet, and never calls a chain signing or broadcast method. Native PostgreSQL is real; chain accounts are synthetic. The output is a fixed status/count/hash receipt bound to the checked-out source SHA and packed archive digests. Keep it with the final clean-revision validation evidence. API credentials are piped privately to the installed backend, never included in arguments, persistent files, output or the receipt. Temporary processes and data owned by the driver are cleaned up. The native QA database intentionally retains its synthetic records for inspection.

For interactive human local startup, use [LOCAL_TESTING](LOCAL_TESTING.md) and the existing [Express example](../../../examples/pact-hosted-express/README.md) or [Next example](../../../examples/pact-hosted-next/README.md), with the exact callbacks they document. Those applications require their own server-only local configuration and a human wallet message approval at the PACT interface. Follow [PHANTOM_ACCEPTANCE](PHANTOM_ACCEPTANCE.md) for separate D/S/B identities and expected foreign-seller denial. Hosted staging acceptance and any real Devnet purchase remain separate owner-controlled gates; this deterministic demonstration cannot satisfy them.

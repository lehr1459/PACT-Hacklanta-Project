# Hosted clock authority and recovery

Decision: one persistent Node process, one private local clock directory, one PostgreSQL authority. This adds a durable time boundary to hosted authentication without changing the SDK, Solana protocol or Base fallback. The hosted service is not a distributed clock or an automatically rollback-resistant backup system.

The service derives a namespace from its issuer and secret-manager pepper. Migration 006 binds that namespace to a random clock UUID in SQL. The UUID also scopes hosted credential/session/proof/code/grant verifiers. Credentials issued before this authority existed are revoked on bootstrap; nonlocal callback proofs require renewal. Apps, resource bindings and history survive. No plaintext bearer secret is stored.

`src/clock.mjs` maintains a fixed 256-byte checksummed record and an exclusive owner lock in an existing private directory. Every returned wall timestamp must be below a ceiling already synchronously written and fsynced to the authority record. The ceiling advances 100 ms at a time. File/lock identity, size and contents are checked; wall and monotonic time are resampled after synchronous filesystem work. Timestamps themselves are never moved into the future to satisfy freshness. The largest wall/monotonic offset is retained: backward, frozen, slow or forward-then-frozen wall time fails closed rather than silently reanchoring. A storage, identity or timing fault latches the authority unavailable until supervised recovery.

Both durable states absent permits bootstrap. Both present and matching permits resume after the old ceiling. A missing file, missing binding or UUID mismatch requires operator recovery. Startup requires PostgreSQL `fsync=on` and `synchronous_commit=on`; runtime connections request synchronous commit. POSIX files/directories are private 0600/0700; Windows ACL protection is an operator requirement. Directory fsync is performed where supported. These checks do not certify the provider's hardware, filesystem, backup or power-loss guarantees.

Only the owner process may use this directory. In-process service handles can share it with exact namespace, source-function identity and database binding; each handle is reference counted. Separate SQL pools are tested for atomic replay, but this does not authorize replicas, cluster workers, network filesystems, serverless functions or copied clock directories. Exclusive filesystem ownership and trusted local storage are required. A failed/crashed process may leave an owner lock: verify every possible owner stopped before moving that lock to private incident evidence. Never delete or rewind the authority record or SQL binding to make startup succeed.

Cold restart below the persisted ceiling is quarantined; after trusted time catches up, retry startup without changing state. A host with incorrect time must be repaired with ingress closed. The retained offset has only about 1 ms rounding allowance: accumulated negative NTP slew can latch the authority even without a discrete backward step. Do not silently reset that floor for availability. NTP/VM time behavior, suspend/resume, actual storage latency and backup recovery need operator acceptance on the selected host; short local benchmarks do not establish long-duration stability. Synchronous disk stalls block the event loop. Final guards deny elapsed decisions and reject mutations before submitting COMMIT, but cannot interrupt blocked syscalls or promise a hard response-time SLA. A COMMIT already sent may finish despite a timeout or lost acknowledgement; inspect actual state before a fresh signed action, never blindly retry a mutation. HTTP/DB lanes do not physically isolate disk.

An old valid database plus an old valid clock file and old pepper can revive authority revoked after that backup. Local checks cannot detect this: an independent native restore test deliberately demonstrates the counterexample. Offline elapsed time cannot be measured if the restarted wall clock is already beyond the saved ceiling. Trusted host time, storage and backup administration remain necessary assumptions. Restore therefore requires disabled ingress, offline quarantine, a new pepper and a new empty clock directory/namespace, followed by deliberate reauthentication, credential reissue and app/callback approval. See [operations](OPERATIONS.md) and the checked-in offline quarantine SQL. Never restore old bearer authority onto public ingress.

Independent tests cover clock rollback/freeze/skew, storage faults, lock contention, actual process crash, missing/mismatched state, cold restart, final-response and mutation age boundaries, and native isolated SQL restore. Local disk microbenchmarks are evidence for this workstation only; they are not hosted capacity certification. Owner-approved staging must repeat them on its persistent volume.

# Shared hosted-consumer backend

Private local support package for the Express and Next.js examples. No runtime dependency, publication or external deployment. Node 24.22.0 and npm 11.19.1 are the verified toolchain.

`createConsumerApp` handles browser sessions, backend-mediated wallet login, logout and actual protected operations. The app's credential belongs only in its server configuration; wallet grants, state, PKCE verifiers and codes are never sent as JSON to its browser. A callback code is consumed by the backend and immediately redirected to the clean root URL. All mutations require the exact application Origin, session-bound CSRF token and empty bounded JSON body. The configured resource is server-selected.

The opaque HttpOnly `SameSite=Lax` cookie is rotated after successful sign-in, together with its CSRF token. A retired cookie has a narrow, single-use, ten-second logout-only capability with its original CSRF. It cannot authenticate session reads, login, callbacks or protected routes; it only allows an already-initiated logout to invalidate the same directly referenced session record after rotation. No alias chains exist. Logout invalidates local authority before awaiting remote revocation. Failed revocation never restores the local session and must be reported truthfully.

Pending login is consumed before asynchronous code exchange. Every awaited body/API operation is bounded and the same live session version is checked afterward. Concurrent callback/new-login/logout cannot resurrect authority. Each protected GET/POST asks the hosted API for a new decision and calls `assertFresh()` synchronously immediately before the response/effect. The demonstration action is only an in-memory counter. Before a real durable DB write or a long operation, obtain a new decision after relevant awaited work, recheck your own session and design transaction/idempotency boundaries: an external API is not atomic with your DB.

The `Map` is bounded to 512 total live-session/retired-alias entries; session TTL is 15 minutes, pending flow at most five minutes, alias at most ten seconds. At most 32 API handlers run and a mutation body is at most 1 KiB with a two-second read deadline. Express streams bodies into this admission pool before reading them. Node ingress/headers/connections and approved operating capacity remain separate requirements. These bounds are a local demonstration, not an SLA or production abuse-control claim. Unsupported known serverless/worker/cluster environments are rejected; a database used by PACT does not distribute the customer's local session store. Restart loses local sessions and denies old cookies. Shared persistent sessions, replicas and real hosting need separate owner-reviewed work.

Run `npm --prefix examples/pact-hosted-common test` from the repository root. Tests use synthetic server-only clients, including delayed-body and callback/logout races; actual API/chain integration is a separate evidence gate. No real wallet is signed or transaction broadcast.
